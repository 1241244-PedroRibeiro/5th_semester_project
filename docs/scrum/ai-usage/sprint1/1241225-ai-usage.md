## 1. Introduction

During the development of Sprint 1 of the LaPrizza project, I used ChatGPT as a support tool for software engineering activities. The goal was not to delegate the entire development process to Artificial Intelligence (AI), but to use it to clarify doubts, explore possible solutions, speed up certain tasks, and support the review of my work.

My approach to AI use was based on collaboration between the tool and the developer. Responsibility for understanding the requirements, making technical decisions, integrating solutions, and evaluating the results remained with me and the team.

## 2. Areas of AI Use

### 2.1. Support for Backend Development

ChatGPT was used to support backend-related tasks, particularly to clarify technical questions, analyse possible implementation approaches, and help understand errors or unexpected behaviour.

The tool's suggestions served as a starting point for analysis. They were not automatically considered correct, nor did they replace the need to understand the existing code, the project context, and the business rules.

### 2.2. Support for Test Development and Review

AI was also used to support testing activities. It could help structure ideas for test scenarios, identify situations that required validation, and analyse possible causes of failures.

The usefulness of these suggestions depended on whether they matched the application's expected behaviour and the project's requirements. Therefore, tests and their expected outcomes had to be reviewed and adapted to the actual system context.

**Example of AI-Assisted Testing**

One example of AI usage was the preparation of unit tests for the `StockQuantity` value object in the stock management module (BCK09). The example below was created with AI assistance and reviewed by me.

The tests cover arithmetic operations, quantity comparisons, invalid values, subtraction underflow, and numeric overflow.

```typescript
import { StockQuantity } from '../../../../src/domain/stock/StockQuantity';

describe('StockQuantity replacement', () => {
  it('adds, subtracts and compares quantities', () => {
    const quantity = StockQuantity.create(5);

    expect(quantity.add(StockQuantity.create(2)).units).toBe(7);
    expect(quantity.subtract(StockQuantity.create(2)).units).toBe(3);
    expect(
      quantity.isGreaterThanOrEqual(StockQuantity.create(5))
    ).toBe(true);
  });

  it.each([-1, 1.5, NaN, Infinity])(
    'rejects invalid quantity %p',
    value => {
      expect(() => StockQuantity.create(value)).toThrow();
    }
  );

  it('rejects underflow and overflow', () => {
    expect(() =>
      StockQuantity.create(1).subtract(StockQuantity.create(2))
    ).toThrow();

    expect(() =>
      StockQuantity.create(Number.MAX_SAFE_INTEGER).add(
        StockQuantity.create(1)
      )
    ).toThrow();
  });
});
```

**Human review:** I reviewed the test scenarios to ensure that they addressed the expected domain rules for stock quantities. This included rejecting negative, fractional, and non-finite values, preventing subtraction from producing a negative quantity, and preventing numeric overflow.

This example illustrates how AI can help prepare test cases while the developer remains responsible for checking their relevance, consistency with the implementation, and expected behaviour.

### 2.3. Support for Technical Documentation

For documentation, ChatGPT was used to help organise ideas, improve writing clarity, and structure technical explanations. This support helped improve the presentation of information without transferring responsibility for its accuracy to the tool.

Documentation produced or reviewed with AI assistance should reflect the decisions actually made by the team and the real state of the implementation.

### 2.4. Clarifying Questions and Analysing Problems

Throughout the work, the tool also served as a reference for clarifying technical concepts and considering alternative approaches to development problems. This use was particularly valuable as support for reasoning: the answers helped explore possibilities, but the final solution still had to be assessed within the context of the project.

## 3. Human Review and Validation

A key principle in my use of ChatGPT was not to accept suggestions without analysing them. Code and proposals provided by the tool were treated as contributions that required review and adaptation, rather than as guaranteed final solutions.

The review process aimed to ensure that solutions were consistent with the project's structure, requirements, and business rules. Where applicable, changes also needed to be checked through compilation, application execution, and relevant tests.

In this way, AI was used to support the work, while critical evaluation and responsibility for the solution remained with people. Using the tool does not remove the need to understand the code, justify decisions, or confirm that the result behaves as expected.

## 4. Benefits and Limitations

Using ChatGPT offered practical benefits to the workflow, including:

- **Productivity support:** helping start tasks and explore possible solutions.
- **Technical understanding:** clarifying questions about code, tools, and concepts.
- **Testing support:** suggesting scenarios and aspects that might require validation.
- **Documentation clarity:** helping organise information and make it easier to understand.
- **Critical analysis:** enabling comparisons between approaches and identifying areas that deserved further review.

Despite these advantages, AI responses can be incomplete, incorrect, or unsuitable for a project's specific context. For this reason, they should not be used as the sole source of validation. Human review, consultation of the requirements, and technical verification remain essential.

## 5. Responsibility and Responsible Use

My approach was to use AI as a complementary tool without replacing learning, reasoning, or active participation in development. The goal was to understand the suggestions received, adapt them when necessary, and ensure that the final work met the project's needs.

This distinction is important: receiving a suggestion does not mean that it is correct or should be implemented. The decision to use it must be based on analysis and its suitability for the system.

## 6. Conclusion

During Sprint 1 of LaPrizza, ChatGPT was used to support backend development, testing, and documentation, as well as to clarify questions and analyse possible solutions. The tool helped explore ideas and work more efficiently, but it did not replace human involvement.

Reviewing and adapting code were fundamental parts of this approach. The main conclusion is that AI is valuable when used consciously and critically: it can support development and learning, but understanding requirements, making technical decisions, and validating the outcome remain the responsibilities of the developer and the team.
