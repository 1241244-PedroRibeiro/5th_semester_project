# ENG02 - As a Project Manager, I want the team to organize and monitor the work required for Sprint 1.

## 1. Requirements Engineering

### 1.1. User Story Description
As a Project Manager, I want the team to organize and monitor the work required for Sprint 1, so that progress, responsibilities, and deviations from the sprint plan can be identified throughout the iteration.

### 1.2. Customer Specifications and Clarifications

#### From the specification document
> No question-and-answer style clarifications were recorded for this User Story. The requirements below are extracted directly from the acceptance criteria defined in *PART III – Sprint 1 – User Stories*.

### 1.3. Acceptance Criteria

- AC1: The Sprint 1 User Stories must be analysed and decomposed into appropriate tasks.
- AC2: Tasks must identify their status and the team member or members responsible for their execution.
- AC3: Dependencies between relevant tasks should be identified.
- AC4: The project board must reflect the actual state of the project and be regularly updated throughout the sprint.
- AC5: Relevant implementation work must be associated with the corresponding tasks or User Stories whenever applicable.
- AC6: The team must maintain sufficient evidence to allow the development process and individual contributions to be analysed during Sprint 1 assessment.

### 1.4. Found out Dependencies
Depends on **ENG01** (Project Repository and Development Environment), since a project board and task-tracking mechanism must already be set up before the sprint's work can be organized and monitored.

### 1.5 Input and Output Data
Inputs:
- Sprint 1 User Stories (BCK, ARC, ENG)
- Team member assignments
- Task dependencies

Outputs:
- Decomposed tasks linked to User Stories
- An up-to-date project board reflecting task status and ownership
- Evidence of development process and individual contributions

### 1.6. System Sequence Diagram (SSD)

Not applicable.

### 1.7 Other Relevant Remarks

This User Story belongs to the **ENG — Project Setup and Engineering Practices** group. Although introduced in Sprint 1, these practices are expected to be consistently followed and maintained throughout subsequent development iterations.
